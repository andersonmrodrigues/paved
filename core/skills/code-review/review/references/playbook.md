# Specialist review lenses

Activate `change-review` for change correctness and `task-review` for requirement quality.
Use `security-review` for exploitable defects, `threat-modeling` for trust boundaries,
`backend-performance` or `frontend-performance` for measured bottlenecks, and `profiling`
for measurement design.

The CLI recommendation is not a completed review or proof of an enforced delivery gate.
Use a different model family only if available and permitted. Scale independent review
to the actual risk; note absent capabilities. After proven findings are fixed, rerun
the relevant verification.
