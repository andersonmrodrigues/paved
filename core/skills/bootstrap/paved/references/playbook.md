# Lean routing boundaries

The router chooses a procedure, not a workflow exemption. Existing workflow approvals,
project instructions and host permissions remain authoritative. Do not start a run for
a read-only repository question merely because a router is available.

Keep a todo list for implementation. A small task needs no additional plan file unless
the active project contract requires one. For a larger task, keep a concise handoff.
Explain the goal and smallest change in one or two lines; avoid status narration.
For independent exploration, delegate only when startup and coordination are worthwhile.
Keep a single continuous trace and short tasks in the primary session.

If a host supports delegation, provide file pointers, objective, budget and stop condition.
Explorers and reviewers are read-only; the primary agent integrates edits and checks proof.
The return sections are Findings, Files read, Boundaries, Non-obvious and Questions.
`paved delegation check --file <path>` validates the serialized result format, not truth.
Use configured models only when supported; do not promise a different model family.

Ask for product choices, conflicting rules, irreversible actions not already authorized,
or persistent verification failures after two distinct repair attempts. Do not invent
approval recording, hook blocking or automatic maintenance. Inspect the installed CLI's
help before relying on a version-dependent capability.
